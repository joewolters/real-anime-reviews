## 1 · DATA MODEL + RULES DELTA (on top of the LIVE v1.10.2 schema)

### NEW collections
- **`blocks/{blockerUid}/list/{blockedUid}`** — `{ createdAt }`; existence = blocked. Owner create/delete/get; `list` owner-only. Read by rules on conversation create + join; read by `onDmMessageCreate` to drop pings.
- **`animeStatus/{slug}`** — `{ status ∈ ['watching','watchlist','on-hold','finished','rewatching'], updatedAt }`. Public get + list (44 docs, it feeds cards); `isAdmin()` write. **This is curation STATE, not catalog data — Excel stays canonical for the catalog (rule #1 honored by scope, not by column).** Rationale: a status flip must be LIVE from any device; an Excel column means resync+redeploy per flip — the opposite of "everything must work."
- **`curatorNotes/{slug}`** — `{ note, updatedAt }`, `isAdmin()` get/write ONLY (private notes never public-readable; separate collection because rules can't field-scope reads).

### CHANGED on live collections (additive)
- **`conversations/{convId}`** (random addDoc ids stay — enumeration-proof): `kind` widens `'admin' → 'admin'|'peer'|'group'`; new `state ∈ ['open','request','declined']` (admin convs stay born-open); peer create = exactly 2 participants, creator ∈ participants, **neither party blocked by the other**, `state:'request'` unless a prior open conv existed; `group`: + `name` (1–60 chars, escaped at render), `creatorUid`, participants 2–15. Participant mutations: creator may add/remove anyone (never below 2, never above 15, add re-checks blocks both ways); any member may remove SELF (leave). Recipient (not creator) may flip `state` request→open|declined. Blake's conversations: kind 'admin' stays for the existing floor; his PEER rows render gold by identity (senderUid), never by kind.
- **`messages`**: + optional `imgRef` (same shape as forum-post images — one per message v1) + `imgThumbRef`.
- **`suggestions`**: + `kind ∈ ['anime','info']` (absent = 'anime' for old docs); rules `hasOnly` gains `kind`.
- **`notifPrefs/prefs`**: per-conversation mute keys `muted['conv:<id>']` (no rules change — shape-free owner doc, rules:280).
- **Wrapped**: NO new collections. v1 computes from existing CG queries (reviews/comments/replies/posts by uid + saves + member-since) — the truthful set per recon; localStorage-cached per user per year.

## 3 · THE SAFETY SPINE (peer DMs + groups + private images — the heaviest heart risk since the Tavern)
- **3a Request-first (the anti-harassment default, Blake's locked pick):** a stranger's first message = a REQUEST. The recipient sees it in a quiet Requests strip — ONE Lantern ping, never repeated, no message preview beyond sender name + first line (length-clamped). Accept → open. **Decline is SILENT** (the sender never learns — no decline receipt, no error; their thread just never opens). Block from the request row in one tap.
- **3b Blocks (new, greenfield):** enforced at conversation CREATE (rules read `blocks` both directions), at group ADD (same), and pings dropped in the CF. Existing conversations with a newly-blocked party: the blocker's client hides the conv (client filter) and their `reads` stop — v1 accepts that rules can't cheaply re-check blocks per message write (a doc read per message); the CF drops pings so the blocked party is shouting into a room the blocker never re-enters. Stated honestly in the risk register.
- **3c Images in private channels (Blake's explicit call + the non-negotiable trio):**
  - **Blur-until-accept, implemented STRICTER than the spec:** in `state:'request'` the client NEVER resolves the image URL — the message renders a neutral "🖼 image attached — accept to view" chip (no fetch, no blurred peek; CSS blur is tamper-trivial, withholding the token is not). Post-accept, images render with the normal lightbox. (The `.rar-spoiler` reveal pattern reused for the chip.)
  - **Report-and-preserve:** report-a-message ships `{targetPath, senderUid, snapshotText, imagePath}` into the existing reports queue — the report CARRIES the evidence, so the admin never needs read-access into conversations (recon: admin has none today; the queue's `dm` viewHref gap gets the snapshot instead). Deleting the message does NOT delete the reported storage object (the sweeper skips reported paths). NCMEC runbook applies — the doc reference rides in the admin queue copy.
  - **Kill-switch:** `commentsMeta/uploads.uploadsEnabled` covers the dm- prefix in storage.rules AND gains a client check in the DM composer (friendly copy, not a rules bounce — today no client checks it at all, recon-verified).
  - Email-verified + caps + dedupe ride the pipeline unchanged.
- **3d Groups:** cap 15 bounds fan-out; creator-only add/remove; leave is unilateral; block(creator) prevents re-add; report works on every message; per-conversation mute. No gold in groups EVER — a group is community space even if Blake is in it (his MESSAGES stay identity-gold; the group row/name stays purple).
- **3e The honest residual:** a solo human moderator + private channels. The spine narrows it (request gate, everything reportable WITH evidence, kill-switch, rate limits, email-verified images) but cannot zero it. Same posture as v1.10.0: stated, not hidden.
