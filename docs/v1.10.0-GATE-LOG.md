## GATE 2 — the ban Cloud Functions. DONE (emulator-verified · STAGED · NOT deployed · NOT committed)

3 CFs that mint + manage the `moderationGate/{uid}` doc the gate-1 rules read. Cores in `functions/lib/moderation.js` (kept in sync with the rules: `CURRENT_RULES_VERSION` == `rulesVersion()`, `ADMIN_UID` == `isAdmin()`'s literal); thin `onCall`/`onDocumentCreated` wrappers in `index.js`.

### The 3 CFs
- **`acceptRules`** (callable, signed-in) — writes `rulesConsent/{uid}` + mints `moderationGate.consentVersion` **server-side** (client can't self-attest). The load-bearing one: nothing else creates the gate doc every community write depends on. Rejects a version != `CURRENT_RULES_VERSION` + an unauth caller.
- **`setBanState`** (callable, admin-literal-gated) — ban: `banned/{uid}` audit doc (triggers the cascade) + `moderationGate.banned=true` + best-effort custom claim; unban reverses all three. Rejects non-admin; refuses to ban the admin.
- **`onBanCascade`** (`onDocumentCreated banned/{uid}`) — H5-redacts (empties + `removed:true`, NOT deletes — preserves audit/report linkage) the banned user's comments/reviews/forum-threads+posts/replies, and locks their conversations. Paged (`CASCADE_PAGE=200`) + idempotent (`alreadyProcessed` + re-redact-empty is a no-op).

### Load-bearing proof
`test:cf`, real gate-1 rules enforced on a client context: fresh user comment DENIED → `acceptRules` mints `moderationGate.consentVersion=1` → same write SUCCEEDS. Rules (gate 1) + CF (gate 2) prove out together.

Hostile: acceptRules bad-version + unauth rejected; setBanState non-admin + ban-admin rejected; banned user denied a write. Happy: acceptRules unlocks; ban/unban round-trip; cascade redacts 4 content types + locks DM + cursor 'done'; cascade idempotent. Holds: `test:functions` 21, `test:rules` 60, `npm test` 104.

## GATE 3 — the "I agree" community-rules consent modal (client). DONE (verified · STAGED · NOT deployed · NOT committed)

The first visitor-facing v1.10.0 gate. A branded consent modal (no native dialog) gates every live community **create** behind `acceptRules`; a banned user gets a branded suspended state. Client-only — `firebase.js` + `script.js` + `style.css` + the practice seeder + a new spec. No rules/CF change.

### Mechanism — a server-truth pre-flight (NOT a localStorage flag)
`ensureCanParticipate()` runs before each community create: (1) bypasses the admin (uid == `NOTIF_ADMIN_UID`, mirrors the rules `isAdmin()`); (2) reads the **owner-readable** `moderationGate/{uid}`; (3) decides via the PURE `consentGateDecision(gate, version)`:
- `banned:true` → `showSuspendedModal()`, block the write.
- no doc / `consentVersion < CURRENT_RULES_VERSION` → `showConsentModal()` → "I agree" calls `acceptRules({version})` → on success the queued write proceeds (no re-click).
- else → proceed.
A per-session uid cache skips the re-read after the first confirmed consent. **Re-prompt-on-version-bump falls out for free** (consentVersion behind the literal ⇒ 'consent'); no localStorage flag anywhere.

### The 4 gated write paths (script.js)
comment create (`comments/{s}/items`), reply create (`.../replies`), review-discussion thread create (`reviews/{s}/items/{rid}/threads`), review publish (`reviews/{s}/items/{uid}`). Each: `if (!(await ensureCanParticipate())) return;` after field validation, before any optimistic UI. Forum threads + DMs aren't built yet (gates 8/18) — these 4 are the complete live community-write surface. Reports left ungated (rules: ban-gated, not consent-gated). Edit/vote paths intentionally NOT gated this gate (the SHIP-PROMPT's surface list is create-shaped; flagged for Blake as an easy extension).

### The wiring
- `firebase.js` — added the Functions SDK (`getFunctions(app)`, default us-central1 = the CFs' region), `connectFunctionsEmulator(...:5001)` in the practice block, exported `functions`.
- Copy = Blake's **verbatim** 2026-06-08 numbered list (6 rules + "By posting, you agree to the following:" + "I agree"); container brand parity (jp-mini 規約, purple, **NO gold**). Suspended modal: jp-mini 停止, plain. CSS mirrors `.rar-report-*` (purple #bb86fc, 3px top-border) — self-contained `.rar-consent-*`, z-9000, Esc/backdrop/cancel close, reduced-motion drops the blur.
- `CURRENT_RULES_VERSION = 1` client const — ⚠️ MUST stay in sync with `rulesVersion()` (rules) + `moderation.js CURRENT_RULES_VERSION`; bump all THREE together to re-prompt everyone.

## GATE 4 — admin reports queue + the 3b consent-modal fixes. DONE (verified + adversarially reviewed · STAGED · awaiting the checkpoint commit)

Bundled Part A (4 gate-3b polish fixes) + Part B (the admin reports queue). Client + a new admin page; NO rules/CF change. A 4-agent adversarial-review Workflow ran before wrap → 4 findings fixed (1 critical XSS, 1 high rules-gap, 1 medium Esc-leak I'd introduced, 1 cosmetic).

### Part A — consent-modal 3b fixes (script.js + style.css)
- **Esc-scope bug (real):** the consent + suspended + report modals attached Esc on `document` (bubble) while the anime modal's closeModal is on `window` — so Esc bubbled up and closed the anime modal too. Fixed with `e.stopPropagation()` in all three onEsc handlers. ⚠️ Review caught a follow-on: the report modal's `close()` didn't remove its onEsc on the non-Esc paths, so after the stopPropagation change an orphaned listener swallowed the NEXT Esc — fixed `close()` to remove the listener on every path (the consent + suspended modals already did).
- **Branded buttons:** "I agree" = primary purple gradient pill, Cancel/Close = quiet ghost. Root cause of Blake's "native beveled" report: the base `.action-btn` rule is scoped to `.comment-item`, so the modal buttons had NO base → `border-color` was inert + they read native. Fixed: gave `.rar-consent-actions / .rar-report-actions .action-btn` a real base (border-style so the per-button border-color paints; NO background so the gradient primary survives), per-button rules `.rar-*-actions`-scoped (0,2,0) so the primary wins cleanly. Branded the report modal's Send/Cancel too (same root, same gate-4 smoke).
- **Composer polish:** Post/Publish → premium gradient pill + hover (`.composer-actions .btn` + `.review-composer .btn`); `.char-count` → subtle muted tabular count.

### Part B — admin reports queue (clone of admin/suggestions)
- **`admin/reports.html` / `.js` / `.css`** + a PURE Node-testable **`admin/reports-model.js`**. Auth-gated (ADMIN_UID redirect, identical to suggestions). Reads `reports` (admin-only per rules), **dedupes by targetPath** (`dedupeReportsByTarget`: N reports of one target = ONE row "reported ×N", sorted reportCount desc then recency), **re-fetches the LIVE content** per target (the reporter snapshot is unverified → both shown, each labeled), escape-first render via `window.reportSnapshotHtml`→`renderMarkdownInline`.
- **Branded actions** (event-delegated): **Ban author** (`httpsCallable(functions,'setBanState')({uid,banned,reason})` → gate-2 onBanCascade tombstones the backlog), **Remove content** (per-type: hard `deleteDoc` for comment/reply/review/thread; soft-redact `{removed:true,…}` for forum/post which are `delete:false` in rules; no-op-then-resolve for dm), **Dismiss** (`updateDoc status:'resolved'`). Ban + Remove gated by a branded confirm modal.
- Reachable via **admin-fab.js** (`{label:'Reports', jp:'通報', href:'admin/reports.html'}` — auto admin-gated + auto-rendered).
- **Report-create dupe-id (script.js):** `addDoc`→`setDoc(doc('reports', reportDocId(uid,targetPath)))` (deterministic, '/'→'~') so one reporter can't spam-file many reports on one target (a repeat = admin-only update = denied → "already filed" message). `window.reportDocId` exposed pure for the spec. (A cross-target per-reporter rate-limit needs a CF — out of client scope, noted.)

### Adversarial review findings (all fixed)
1. **CRITICAL** — reports.js `escapeAttr` (textContent→innerHTML) didn't encode quotes → an attacker-controlled `targetUid`/`targetPath` (`is string` only in the rules) could carry a `"` to break out of a `data-*` attribute and inject an event handler running in the ADMIN's session. Fixed: `escapeAttr` now also encodes `"`+`'`.
2. **HIGH** — Remove did an unconditional `deleteDoc`, but forum/post are `delete:false` (soft-delete only) and dm messages immutable → the button threw + stranded the report for those types. Fixed: per-type branch (soft-redact / no-op) so every reportable type resolves.
3. **MEDIUM** — the report-modal Esc-listener leak (above) — fixed.
4. **LOW** — consent buttons' inert `border-color` (no `border-style`) — fixed via the base.
Wiring/clone-fidelity agent: clean (every id resolves html↔js, classic scripts before the module, no native controls). Rules agent verified admin delete IS allowed for comment/reply/review/thread, setBanState shape matches, dismiss allowed, report-create still passes.
