## 🔴 RECURRING #1 — the dim headings: the REAL cause, with pixel proof
**Three rounds recolored the text; the text was never the problem.** The v1.8.3 "persistent header bar" CSS targets bare `header` — and round 2's account IA used semantic `<header class="panel-head">` in every panel. The site header's dark gradient **scrim (::before) painted ON TOP of the static heading text** (positioned-above-static paint order); the site header itself survived because its own content is z-lifted. Computed-style specs kept passing (#f6efff) because **computed color ≠ painted pixels** — the claim-fixed-while-still-dim pattern, explained.
- **Pixel proof (sampled from real screenshots, both engines):** kicker max luminance **195/255 before → 242/255 after** (242 = exactly #f6efff); pixels brighter than 200: **0.0% before → 16.6% after**. Chromium AND Firefox.
- **The fix:** every bare `header` rule scoped to `body > header` (style.css ×13 rules + mobile.css; page headers on all 10 pages are body children — admin pages keep their look). The Tavern's `hub-header` was silently riding the same leak (your old "tavern text" bug — same class!) — it now owns its row layout explicitly; thread headers got tighter (34px vs a leaked 80px), deliberately.
- **The durable tripwire:** a spec now pins that a *nested* `<header>` carries **no scrim / no sticky / no 80px** and that the real site header **keeps** its backdrop — the leak can't regrow silently.
- Profile-modal kickers (MEMBER 旅人, 📌 PINNED REVIEW) were the last *declared*-dim ones (#cbb0ff) — now #f6efff with glow. Every panel subtext now sits in a **soft glowing pill**, and the Constellation's reads **"Customize your profile, bio, send messages and more — all from here!"** (your words).
